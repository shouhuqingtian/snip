# 2.0.75 Windows 当前用户代理兼容

用户在 Clash Verge 开启系统代理和规则模式时，应由 Clash 对收到的目标执行规则，不要求用户为使用国内服务关闭代理。此前诊断中的代理隧道 SocketException 只能说明连接阶段失败，不能证明 Clash 分流错误。2.0.73 多个在线功能持有长期存活的 SocketsHttpHandler / 默认代理，存在保留进程初次读取代理配置的隐患。

Windows 上改用 Microsoft System.Net.Http.WinHttpHandler 8.0.3 的 UseWinInetProxy 策略，在支持的 Windows 10/11 上使用 WinHTTP AUTOMATIC_PROXY，由系统执行当前用户代理和 PAC 策略。目标地址保留给系统代理，由 Clash 执行规则分流。不自行维护国内域名白名单、不失败后绕过代理、不重放录音和付费请求；HTTPS 证书验证、禁用自动重定向与 Cookie、现有取消、响应长度限制均保留。非 Windows 验证环境沿用 SocketsHttpHandler。

语音识别、在线翻译/OCR、AI 发音、账号同步统一使用新传输入口。模型下载和仅访问本机的翻译工作进程不在此范围。Windows 使用当前用户系统代理，不再让进程中的 HTTP_PROXY / HTTPS_PROXY 环境变量覆盖此策略。系统代理开启但本地代理程序确实不可用时，仍应提示连接失败；本修复不保证错误端口、离线节点或未配置规则能够工作。

## 文件

- `OnlineTransport.cs` / `Snip.Core.csproj`：Windows 原生代理传输及固定依赖。
- `AccountSyncApi.cs`、`OnlineTranscriptionService.cs`、`OnlineSpeechSynthesizer.cs`、`OnlineResponse.cs`：四类在线请求入口。
- `NetworkProxyChecks.cs` / `Program.cs`：只在一次性 Windows CI 桌面执行，真实修改并恢复当前用户代理；本地测试服务器仅传合成内容。验证已有客户端的直连、启用代理、更改端口、停用代理及代理收到原始地址。
- Windows 工作流：正式打包前运行该检查，专项流程连续多轮回归。

验证与交付记录完成后补充。未使用用户模型密钥或付费服务，不改用户 Clash 配置，不部署阿里云服务。

补充：原生 HTTP 的发送/接收默认 30 秒计时器已关闭，继续由调用方既有的有限请求截止时间和取消令牌约束，防止长语音提前失败。专项增加真实延迟 32 秒响应，验证不受旧默认 30 秒限制。随包提供 NuGet 原版 MIT 许可。初始 v2.0.74 验证在发布前取消，未移动标签，最终交付使用 2.0.75。
