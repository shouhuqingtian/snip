# 2.0.7 编辑性能优化

用户反馈：截图编辑阶段内存升高、响应偏慢；要求中英翻译完全离线。尚无用户机器上具体占用数值，因此 Windows 回归采用公开的合成图片，不声称复现全部实际负载。

## 已定位的开销与修改文件

- `src/Snip.Infrastructure/AnnotationRenderer.cs`：之前每次标注提交都生成完整截图位图，每个马赛克还额外重绘整图。现在普通标注以冻结的 DrawingGroup 保留矢量，只栅格化马赛克对应区域；导出才合成整图。未标注时复用已冻结原图。
- `src/Snip.App/Views/EditorCanvas.cs`：预览复用矢量图层；卸载时解除 ViewModel 事件订阅、释放缓存，重新加载时恢复订阅，避免旧画布随仍在使用的编辑模型存活。
- `src/Snip.App/Services/SelectionSession.cs`、`src/Snip.App/Views/SelectionWindow.cs`：关闭选区时解除画布 DataContext 和对话框 owner 的引用。此前对话框 owner 捕获选区窗口，连带保留整个多屏桌面 Frame。移除工具入口的一次无用整图合成，仍在关闭前提交行内文字。
- `src/Snip.App/ViewModels/EditorViewModel.cs`：拆出提交待编辑文字/手势的操作，功能跳转无需预先导出再丢弃一张图片。
- `src/Snip.App/Views/UiIcon.cs`：冻结并复用图标几何，避免每次重绘解析路径。
- `tests/Snip.Windows.Checks/RenderPerformanceCheck.cs`、`Program.cs`、`packaging/Validate.ps1`：加入真实 WPF 像素对比、卸载画布可回收检查、两个独立子进程的 4K 预览性能对比，输出 `validation/editor-performance.json`。基准保留优化前的渲染方式，仅在测试中使用。
- `Directory.Build.props`、`docs/使用说明.md`：版本与使用边界更新。

## 验证

Linux 可编译 Windows 项目并运行 Core；原生桌面验证另在 Windows CI 执行。性能基准分别启动新进程，采用 3840×2160 图片、4 次标注提交及每次 3 个马赛克区域，报告预览耗时、进程 Private Bytes/Peak Working Set、托管分配；不通过不稳定的时间阈值判定通过。新旧输出 SHA256 必须相同。小图额外检查相互重叠的马赛克和超出图片边缘的马赛克。测试中的 GC 只用于验证对象可回收性，产品没有强制 GC 或工作集裁剪。

Windows 实测结果及下载链接将在验证完成后补充。

## 翻译边界

完全离线且有较好通用中英翻译质量，仍需要本地语言模型。把模型随完整发行包交付可以省去软件内的下载步骤，但不会减少模型本身，也不会因此提高质量。现有轻量包和已安装的量化模型保持兼容，未接入在线服务，未通过降低搜索质量换取更好看的性能数值。
