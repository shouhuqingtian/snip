## 3. 必须明确的交互

### 3.1 主截图流程

已确认：选区形成后显示浮动工具栏，直接在选区里标注；独立编辑窗口保留为可选入口。

工具栏需适应显示器边缘、负坐标和混合 DPI，并避免挡住用户正在绘制的区域；导出图片不含工具栏及遮罩。

绿色对勾建议定义为“合成截图、复制到剪贴板、关闭截图遮罩并返回原应用”。保存按钮建议只负责另存为，不隐式取消编辑；这些行为待用户确认。

文字建议直接在图像位置输入和修改；颜色、线宽、字号采用对应工具的浮动属性面板。是否采用这些行为待确认。

### 3.2 OCR 与翻译

- 最新选择覆盖此前在线方案：用户要求先做离线，在线服务后续补充。
- 离线 OCR 优先评估 Windows 自带文字识别组件，目标为中英文；检查语言组件可用性，缺失时明确提示所需安装步骤，不要求用户填写在线密钥。
- 离线翻译需要另外的模型和语言方向。当前待用户选择：本轮只做离线 OCR、翻译后续接在线服务；或本轮增加离线中英互译并接受额外模型下载。
- 离线推理不上传截图或识别文字；模型/语言组件的安装与本地推理分别说明，不能把在线翻译缓存称为离线翻译。
- 结果窗口提供复制、失败提示和取消；未实现的功能不显示为可用。
- 保留在线服务扩展契约，实际供应商及凭据配置在后续阶段确认。

### 3.3 长截图

已确认采用自动滚动，优先支持 Chrome/Edge 普通网页；其他应用不支持时明确提示。本轮不以手动滚动替代自动滚动功能。

拟定验收范围：

- 选取浏览器网页内容区域，激活对应浏览器窗口，自动向下滚动采集。
- 根据重叠内容去重并拼接，提供进度、预览、完成及 Esc 取消。
- 检测到底、窗口变化、页面不滚动和拼接置信度不足，避免生成静默重复或错误拼接的图片。
- 保留原网页可见内容，不把遮罩、工具栏或浏览器地址栏拼入长图。
- 设置采集时间、帧数和最终图像大小上限，避免无限加载页面持续占用资源。
- 嵌套滚动容器、虚拟列表、动态视频和复杂固定元素不默认视为已支持；无法可靠采集时明确说明原因。

不得将普通多张图片纵向堆叠称为已实现可靠滚动拼接。

### 3.4 贴图、表情和分享

- 贴图候选范围：桌面置顶显示、拖动位置、滚轮缩放、透明度、鼠标穿透、Esc/右键菜单关闭，待用户确认。
- 表情候选范围：内置通用表情与用户导入图片贴纸，不复制微信专有素材，待用户确认。
- 分享已要求直接选择微信联系人并发送，不能以复制图片或系统分享面板作为此功能完成。
- 当前项目没有已验证的微信联系人/发送接入。需要用户提供 Windows 微信版本，并确认是否接受通过微信窗口自动操作实现；该方案要求微信已登录、逐版本适配及 Windows 实机验证。
- 此次云环境无法访问微信官方开发文档，尚不能确认可用于本需求的官方接口。不能将未核实的接入能力写成已可实现或已验证。
- 若采用界面自动化，需选择明确的收件目标并预览图片，用户点击发送后才执行；目标无法核实时停止并显示原因。开发测试使用模拟适配器及受控测试场景，不擅自给真实联系人发送图片。

## 4. 可追加但尚未纳入范围的功能

以下候选功能已发给用户确认，未确认前不直接实现：

- 鼠标悬停自动选择窗口 / 子窗口，按 Tab 切换目标。

- 标注拖动缩放、矩形填充、文本背景、模糊遮挡。

本轮提出的补充清单为窗口自动选择、放大镜、方向键微调、标注移动/缩放和矩形填充；其余条目不随之自动纳入。

## 5. 确认后的实现原则

- 延续 C#、WPF、.NET 8、MVVM 和现有 Core / Infrastructure / App 分层。
- 复用已有标注模型、渲染和撤销历史；选区编辑与独立编辑共享同一文档，不维护两套结果不一致的实现。
- 新增 OCR、翻译、长截图、贴图和分享服务，按确认方案注入；不添加虚假的可用入口。
- 每完成一个功能记录修改文件、验证结果及限制。
- 完成后生成新版源码、便携包和安装包，通过现有 GitHub 仓库下载目录交付；版本号随实际新增范围更新。
- Linux 继续执行构建和核心测试；Windows 相关检查及用户实机反馈分别记录，不将编译通过视为桌面交互验收通过。
