# 2.0.27 增强离线 OCR

系统 OCR 存在非空错字、自动中英模式在中文引擎返回文字后停止等局限。本版增加可选的 PP-OCRv6 small 离线中英识别，统一处理中文、英文和混排，避免用中文结果“非空”代替语言判断。

## 使用

截图 → 识别文字 → 更多设置 → **下载 / 修复增强 OCR**。

首次下载约 31 MiB，四个文件共 32,257,432 字节；不需要翻译模型或在线密钥。下载完成后立即重新识别当前截图。模型安装后默认采用增强识别；取消勾选“增强离线识别”可切回系统 OCR，选择自动保存，重启仍沿用。增强引擎为中英混合识别，使用时禁用只适用于系统 OCR 的语言下拉。

增强模型未安装时继续使用免下载的系统 OCR。模型损坏、识别进程失败或达到内部时限时尝试系统引擎，并在状态栏显示回退；缺少系统 OCR 语言组件时保留窗口并提示原因。用户主动取消不会另启系统识别。

## 资源与隐私

- 托盘启动时不创建增强推理器；识别才启动独立进程，结束、取消、窗口关闭后结束该进程。主程序不加载 ONNX/Skia 原生推理库。Windows 作业对象将识别进程绑定到主程序，主程序意外退出时也由系统终止识别。
- CPU 使用两条 intra-op 线程、一条 inter-op 线程，识别进程为低于正常优先级。小图限制无谓放大；长图使用有重叠的竖向分块，保持截图原始坐标。
- 截图和结果只经进程管道传递，不写临时图片或 OCR 文本文件、不发送给在线 OCR 服务。诊断只记录尺寸、耗时、计数、进程退出情况等技术数据。
- 模型 SHA256 使用固定上游清单和固定镜像提交，识别前再次校验。权重可从官方 ModelScope 分发或固定 GitHub 镜像下载；不能因下载失败关闭 TLS/校验。
- 核心权重约 30 MiB，加上方向分类和字符表约 31 MiB；推理运行库随 EXE 提供，不是 1 GB 级离线翻译模型。新增组件会增加 EXE 体积，空闲占用和一次识别的临时开销须分别看。

## 评估依据与边界

[独立评估报告](OCR增强评估.md)记录模型比较和原始工作流。Windows 实际 C# 引擎在限制放大后：29 张合成图中 26 张完全一致；普通裁图连续识别中位耗时约 118 ms，测量结束时工作集最高约 151 MiB，包含 4K/长图的整组峰值约 599 MiB。第一张图从模型初始化至结果约 386 ms，**不含进程启动/图片传输，不能当作应用端到端耗时**。

较轻 tiny 模型在另一种常见字体下反复误识别中文，未默认采用。相似字符 I/l/1、0/O 仍可能混淆，不能保证所有图片完全正确。上述是有限公开合成样本，未保存或宣称复现用户原图。Windows 测试机缺中文系统语言组件，原生中文 OCR 比较为 Unrun；增强中英测试不依赖该组件。

应用使用独立进程和长图分块后，还需以本版真实流程回归、最终 EXE 检查为交付依据；评估工具的进程内结果不能替代应用验证。
