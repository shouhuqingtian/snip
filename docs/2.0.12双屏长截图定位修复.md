# 2.0.12 双屏长截图定位修复

## 反馈与定位

同一 Chrome 页面在外接显示器可以截图，在笔记本屏幕提示“当前只支持 Chrome/Edge 普通网页”。该提示出现在滚动、拼接之前：程序将覆盖选区中心的第一个顶层窗口矩形当成目标，判断其进程不是浏览器后退出。仅凭此反馈不能确定用户机器上具体是哪一个窗口，也不能确认实际缩放比例。

## 修改文件

- `src/Snip.Infrastructure/WindowCaptureInfo.cs`：使用 `WindowFromPhysicalPoint` 命中选区中心的真实窗口，再取得其顶层窗口；不再用覆盖矩形代替浏览器命中。窗口枚举的回退坐标读取限定为物理像素。
- `src/Snip.Infrastructure/PhysicalDesktopScope.cs`：同步原生调用临时使用 PerMonitorV2，结束恢复原线程上下文；不跨越 await。
- `src/Snip.Infrastructure/BrowserScrollCapture.cs`：正文 HWND 边界统一按物理坐标读取，鼠标定位和恢复改用物理坐标 API。新增目标命中和验证阶段日志，只记录选区/目标坐标、进程 ID、DPI、是否支持；不记录标题或网页地址。实际命中非浏览器时停止，不向被其他窗口遮住的浏览器发送滚轮。
- `src/Snip.Infrastructure/DesktopCaptureService.cs`、`NativeMethods.cs`：选择鼠标位置直接读取物理坐标；显示器枚举和 GDI 区域采集使用同一坐标约定。
- `tests/Snip.Windows.Checks/BrowserTargetChecks.cs`、`ChromeCaptureCheck.cs`、`Program.cs`：独立进程创建透明顶层窗口覆盖 Chrome，先断言旧的矩形判断确实选错进程，再验证真实浏览器命中及可见正文截图。DPI unaware 后台线程验证命中、显示器边界和调用后上下文恢复。
- `Directory.Build.props`：版本 2.0.12。

## 验证与边界

本地完整 Release 构建无警告、无错误；70 项 Core 和 14 项在线协议检查通过。真实 Chrome、Windows UI、原生 OCR、模型、发布 EXE 的检查由 Windows CI 执行，完成后补充记录。

CI 的透明覆盖窗口和线程 DPI 上下文回归可直接检验旧目标选择缺陷，不能代替笔记本 4K 与外接屏的真实混合 DPI 验收。没有更改拼接算法、在线翻译服务或密钥配置。

退出旧版托盘后运行新版本，在笔记本屏重复“整个网页”采集。若仍失败，导出新版本诊断包，其中 `browser-target-hit`、`browser-target-validated` 能区分命中错误和之后的正文边界问题。
