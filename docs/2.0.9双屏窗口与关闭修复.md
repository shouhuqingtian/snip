# 2.0.9 双屏窗口与关闭修复

用户反馈：4K 笔记本配 1200p 外接屏，OCR/翻译窗口顶部被屏幕裁掉，无法拖动，Esc 无法关闭。尚未获得精确的缩放比例及主屏设置。

## 已确认的代码问题

文字工作台固定最小高度 700 DIP，175% 缩放后至少需要 1225 物理像素，可能超过另一显示器的工作区。此前只使用 WPF CenterScreen，未按目标显示器工作区限制窗口；结果窗口也没有注册 Esc 关闭。用户图片显示顶部标题栏及操作区不可见，底部结果仍在，符合窗口越界；不据此认定 OCR 又发生死锁。

## 修改文件

- `src/Snip.Core/WindowPlacement.cs`：以物理像素计算显示器工作区内的大小/位置，支持负坐标、DPI 安全边距和屏幕断开后的越界修复。
- `src/Snip.Infrastructure/WindowWorkAreaService.cs`：普通窗口第一次显示时选择鼠标/父窗口所在显示器，先移动到目标屏，再取真实 HWND DPI，调整最小尺寸及位置。跨屏 DPI、窗口拖动完成、显示器/工作区变化后修复越界；保留原生拖动，不在拖动过程中反复抢位置。关闭时解除窗口事件和 HWND 钩子。
- `src/Snip.App/Views/Ui.cs`：为普通窗口统一安装工作区保护；WindowStyle.None 的选区和贴图保持独立定位。
- `src/Snip.App/Views/TextResultWindow.xaml`、`.xaml.cs`：Esc 和可见关闭按钮关闭并取消任务；提供“移回当前屏幕”。正文使用有界高度的滚动布局，缩小窗口不会裁掉操作区，长 OCR 文本仍在文字框内滚动。
- `tests/Snip.Core.Tests/WindowPlacementTests.cs`：4K 175%/200%、1200p 100%/150%、1080p 175%、1366×768 150%、负坐标、显示器断开回归。
- `tests/Snip.Windows.Checks/WindowPlacementChecks.cs`、`Program.cs`、`Snip.Windows.Checks.csproj`、`packaging/Validate.ps1`：测试宿主使用与软件相同的 PerMonitorV2 manifest；实际 HWND 越界/过大复现并恢复、低高度正文滚动、文字焦点内 Esc、处理中关闭取消回归。
- `Directory.Build.props`、`docs/使用说明.md`：版本与操作说明。
