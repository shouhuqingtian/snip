# 2.0.60 图片选字与贴图副本交付

本版交付独立窗口图片选字和贴图编辑副本，完整功能、引擎边界及变更文件见 [2.0.59图片选字与贴图编辑副本](2.0.59图片选字与贴图编辑副本.md)。用法：独立编辑窗口底部点击“选取文字”，直接拖选，再 Ctrl+C / 右键 / 点击“复制文字”；Ctrl+A 全选，Esc 返回标注。贴图右键“编辑（副本）…”进入相同编辑器，原图保留，可复制、保存或重新钉图。只按需使用本机 OCR，高亮不写入 PNG；修改后旧识别失效，遮挡块保守剔除。

## 交付核对发现的层级问题

2.0.59 正式构建 [39915247180](https://github.com/shouhuqingtian/snip/actions/runs/39915247180) 的核心、Windows 与安装检查均通过，源码提交为 `b29a3a7980cb3a02c47759b23819bb04f0fcf032`。重新下载的 6 个附件、5 项 SHA256、346 个源码文件及羊图标匹配，完整桌面 25 组中 23 组通过、2 组因环境能力缺少未执行。但最后人工查看原始预览图，确认置顶原贴图仍可遮住已经显示的编辑副本：WPF Owner 关系单独设置在 Show 后，不会把普通编辑窗口提升到置顶层级。原专项检查保留了原图和编辑功能，未覆盖实际窗口重叠下的鼠标命中。

使用新版本 2.0.60 修复，不覆盖或重打 2.0.59 标签 / 附件。`FeatureHub.OpenPinEditor` 让副本继承原贴图的 Topmost 属性，仅影响贴图编辑副本，普通编辑窗口行为不变。原贴图关闭前仍解除 Owner 关系，保留副本独立性。

`ImageTextSelectionChecks` 新增真实重叠场景：把置顶源贴图移到编辑区域上方，通过原生 WindowFromPoint / GetAncestor 核对鼠标实际落入编辑器，随后继续验证选字、原图不变、重新钉图和关闭原图后副本仍可操作。既有文字剪贴板、缩放滚动、遮挡、取消、缓存与原生 OCR 断言保留。

本版额外修改 `Directory.Build.props`、`src/Snip.App/Services/FeatureHub.cs`、`tests/Snip.Windows.Checks/ImageTextSelectionChecks.cs`、`docs/使用说明.md` 及本记录。
