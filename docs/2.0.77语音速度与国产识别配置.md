# 2.0.77 语音固定开销优化与国产识别配置

## 速度优化

当前语音输入仍是结束录音后发送整段音频，不宣称边说边上传或流式输入。服务端推理/排队时间取决于平台、模型和网络，不用本地假服务声称真实平台提速。

- 原有输入框校验每次启动独立进程。现在一次听写中，两次校验复用一个有生命周期和查询超时的辅助进程，减少第二次进程冷启动；仍重新查询实际焦点，不复用旧输入框结果。结束或取消时清理，不在空闲时保留麦克风或校验进程；密码输入框不上传、焦点变化不自动输入的保护继续保留。
- 16 kHz PCM 上传前去除首尾低能量静音，保留各 200 ms 上下文、所有中间停顿及至少原有短录音长度。全静音仍拒绝上传。合成测试中 5 秒含静音音频变为 1.4 秒，逐字节验证中段完全保留；这是上传音频长度对比，不是真实识别延迟倍数。
- 增加纯数字的阶段耗时：录音与启动、初次校验额外等待、识别请求、最终校验与输入、音频字节数。日志不含声音、原文、模型名、域名或密钥；识别提示显示已等待秒数。

## 国产服务与自定义切换

保留硅基流动 `FunAudioLLM/SenseVoiceSmall`，新增两组原生协议适配：

- 阿里云百炼 `qwen3-asr-flash`：`https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`。使用 JSON `input.messages[].content[].audio` 内联 WAV，解析 `output.choices[].message.content[].text`。语言自动时省略语言参数。
- 智谱 `glm-asr`：`https://open.bigmodel.cn/api/paas/v4/audio/transcriptions`。使用 multipart 音频和 `stream=false`，解析 `choices[].message.content`，语言由模型判断；不把它假装成返回根级 `text` 的接口。

依据官方 SDK 而非猜测模型名：

- [DashScope 官方 ASR 示例](https://github.com/dashscope/dashscope-sdk-python/blob/9d82fbd22b03ee1804f588da92cc86dcfc5a61c6/examples/legacy_1x/qwen_asr.py)、同提交的 `examples/01_atomic_capabilities/audio/asr_http_stream.py` 内联 WAV 示例，以及 `legacy_1x/aigc/multimodal_conversation.py` 的 task / function 定义。
- [智谱官方识别实现](https://github.com/zhipuai/zhipuai-sdk-python-v4/blob/ccbec4c7b53ca23dabac69aa1a0b5599cf29a848/zhipuai/api_resource/audio/transcriptions.py)、同提交 `tests/integration_tests/test_transcriptions.py` 的 `glm-asr` 示例、`types/chat/chat_completion.py` 的返回结构及 `_client.py` 的默认地址。

官方文档站在开发环境经网关访问失败，使用可访问的官方 SDK 仓库核对协议。未使用用户密钥或调用真实付费服务；地区、开通权限、限额与模型可用性仍以平台为准。已有 MiniMax 自填地址不因此获得适配。

“语音输入”增加可命名的自定义配置与协议选择。新增草稿后可选择 OpenAI 兼容、百炼或智谱协议，编辑地址和模型，独立保存加密密钥；从列表选已保存配置并点击“保存设置”启用。空白的百炼/智谱草稿提供对应示例，不覆盖已经填写的自定义地址。旧配置缺少协议字段时仍使用 OpenAI 兼容方式；不悄悄换服务、混用平台密钥、自动重试或回退平台。ASR 配置继续只保存在本机。

- 语音设置 ViewModel / XAML、录音状态窗口：命名配置、协议和模型示例、等待计时。
- Core / 协议 / Windows 检查：音频保真、旧配置、请求结构、非法返回、实际 UI 配置保存、真实 UIA 复用与新鲜性、进程回收。
