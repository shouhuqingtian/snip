# 2.0.4：识别/翻译退出软件与结果面板修复

用户反馈：截图后点击识别或离线翻译，窗口没有结果，随后整个软件退出；看不到最新操作日志。用户确认结果布局采用左侧截图、右侧识别文字，翻译时保留原文及译文，失败和缺模型时保留窗口。

## 已复现的根因

旧 `ProgressBar.Value` 绑定没有指定方向，WPF 默认使用双向绑定，而 `TextResultViewModel.Progress` 对绑定引擎是只读属性。原生 Windows 显示真实结果窗口时抛出 `InvalidOperationException: A TwoWay or OneWayToSource binding cannot work on the read-only property 'Progress'`，发生在 Loaded/OCR 初始化之前。

[失败回归](https://github.com/shouhuqingtian/snip/actions/runs/38403145851) 在未修改结果窗口的源码上复现异常，停止交付；之前服务/响应测试不曾显示这份真实 XAML，漏掉了此问题。

## 日志位置

日常运行日志在 `%LOCALAPPDATA%\SelfSnip\Logs\events.jsonl`，阶段发生后后台追加，时间戳为 UTC。便携 ZIP 中的 `validation/*.log` 是构建检查记录，不随软件使用刷新。程序重启后可从主窗口/托盘导出诊断 ZIP，含近期轮转日志和版本信息。

## 验证命令与范围

```powershell
./packaging/Validate.ps1 -Scope Core
# 原生 Windows 桌面，完成 Release 构建后
./packaging/Validate.ps1 -Scope Desktop -NoBuild
```

`--text-ui` 使用公开合成图像和可控服务验证实际窗口、工具栏和失败状态；`--ocr-ui` 使用 Windows 英语识别组件和已校验的真实离线模型，核对真实窗口中的识别/翻译结果。缺少英语组件时明确记录 Unrun，不把可控服务检查当成原生识别通过。多显示器混合 DPI、中文 OCR 效果、用户具体截图仍需实机验收。
