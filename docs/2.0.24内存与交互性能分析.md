# 2.0.24 内存与交互性能分析

## 总体判断

仍有优化空间，本轮优先减少截图编辑时的重复工作与临时分配。没有降低输出分辨率、跳过模型校验、限制已有撤销步数或在生产流程强制 GC。

| 阶段 | 主要开销与现状 | 本轮处理 / 边界 |
| --- | --- | --- |
| 托盘常驻 | WPF / 托盘 / 日志；模型不常驻，词典首次查词才加载 | 不增加后台轮询或常驻推理器；诊断增加即时内存与累计 CPU 数据，尚未在用户机器测量空闲占用 |
| 进入截图 | 隐藏窗口并等待桌面合成，采集虚拟桌面像素及显示器信息 | 整屏采集移出 Dispatcher；仅保留采集前的一次 DwmFlush，退出后的迟到结果不再创建覆盖层 |
| 原图内存 | 3840×2160×4 = 33,177,600 字节，约 31.64 MiB / 原始像素副本 | 多屏按虚拟桌面包围矩形计算，可能包含屏幕空隙；这只是像素基础开销，不等于整个进程内存 |
| 编辑 | 已有矢量预览、最多 100 次撤销；剩余热点为轨迹前缀复制、文字布局失效、贴纸反复解码 | 当前画笔增量保存点，提交时仍由历史防御性复制；无文字输入时不再使布局失效；同一不可变贴纸复用冻结像素 |
| 长图合成 | 输出图像本身需要内存，分块栅格化还会产生大数组 | 每次合成复用一个最多 2048×2048×4 的临时缓冲；输出尺寸和像素不变；选区阶段结束后不再跨网页工作流持有完整桌面会话 |
| OCR | Windows 本机识别；目前仍有 PNG 编码、解码与分块像素复制 | 本轮保留现有已回归的识别路径，后续可重点评估避免编码往返，不能简单放大或降采样而牺牲识别质量 |
| 在线翻译 | 等待网络和服务生成，主界面不加载本地模型 | 本轮不增加请求；模型响应速度与网络、输入 / 输出长度有关，编辑优化不能代替服务端提速 |
| 离线模型 | 模型校验、冷进程加载及 CPU / GPU 推理；每次完成 / 取消退出进程 | 2.0.23 的 Windows 样例优化后原生峰值约 1099 MiB，完成后进程退出。保留按次释放，避免为了热启动持续占用约 1 GB 内存 |
| 基础词典 | 查询后英文数据约 12.75 MiB，加中文索引约 23.11 MiB 托管增量（2.0.23 样例） | 已分别延迟构建；这是词典数据增量，不是全应用内存。静态词典索引使用后保留到退出，有利于再次查词响应 |

保存 PNG 的最终渲染与编码仍有同步路径，大图密集标注仍可能造成停顿；本轮先处理高频交互，不把局部基准误写成所有操作都提速。在线 / 离线的音标功能没有在本轮扩展。

## 修改文件与对应功能

1. `src/Snip.App/ViewModels/EditorViewModel.cs`：画笔仅为当前未提交手势使用增长列表，不再在每个点复制全部前缀；提交历史仍不可变，取消清除临时列表。移动期间不广播未变化的命令状态；无需过滤时复用已有历史列表。
2. `src/Snip.App/Views/EditorCanvas.cs`：没有文字编辑框、也没有待创建文字时，跳过文字布局失效，仍刷新绘图。
3. `src/Snip.Infrastructure/AnnotationRenderer.cs`：不可变贴纸 PNG 以弱键缓存冻结解码图，不把已关闭文档留在强引用全局缓存中；区分同数组不同切片，避免复用错误图片。长图栅格化每次调用只分配一个有上限的临时像素数组，不使用全局像素缓冲池。
4. `src/Snip.App/Services/CaptureCoordinator.cs`：后台采集并检查迟到结果；选区会话在独立方法结束后释放，再进入编辑 / OCR / 网页等工作流，避免长任务持有整屏背景。
5. `src/Snip.Infrastructure/DesktopCaptureService.cs`：删除重复的桌面合成等待，保留真正复制像素前的一次等待；显示器坐标与逐屏 BitBlt 不变。
6. `src/Snip.App/Services/DesktopDiagnostics.cs`：启动环境及导出的 `environment.json` 增加 `Resources`：WorkingSetBytes、PrivateMemoryBytes、ManagedHeapBytes、ProcessorSeconds、各代 GC 次数。只按原有调用时机读取，不强制 GC、不持续采样，不含图片或文字。CPU 秒为累计值，不是瞬时百分比；离线子进程数据仍在 native-released 记录中。
7. `tests/Snip.Windows.Checks/InteractionPerformanceCheck.cs`：真实 WPF 布局、连续画笔 / 撤销 / 重做 / 取消 / 文字输入、贴纸共享及切片正确性、缓存与编辑器可回收、采集期间 Dispatcher 响应及退出后不创建覆盖层；三个独立进程局部性能基准及输出 SHA256 一致性。
8. `tests/Snip.Windows.Checks/Program.cs`、`RenderPerformanceCheck.cs`、`.github/workflows/windows.yml`：将新增检查接入现有 editor-performance 组，并在浏览器 / 模型检查前先运行，错误通过注释直接展示，尽早发现问题；完整桌面检查仍保留，失败禁止打包。
9. `Directory.Build.props`、`README.md`、`docs/使用说明.md`：版本及分析 / 诊断 / 交付说明。

## 测量方法与验证

旧版局部基准固定为 2.0.23 的三个算法：每点追加时复制整段轨迹、每次贴纸重建都解码 PNG、每个大图瓦片新建数组。本轮用独立子进程测量，分别保留耗时、托管分配、开始 / 结束 private bytes 和进程 peak working set；输出像素 SHA256 必须一致。画笔用 10000 次移动，贴纸用 1024×768 PNG / 24 次重建，大图用 1537×8305 并包含非整块边缘。画笔优化测量的是实际 ViewModel 手势处理，旧侧为轨迹复制及历史提交；不是整应用端到端延迟。

托管分配是操作累计创建的字节，不等于常驻内存或任务管理器峰值。进程峰值包括测试基础设施及准备数据，不能直接套用为用户电脑的程序占用。耗时仅报告，不设置易受机器波动影响的速度阈值；检查点数、像素一致、分配显著下降、缓存可回收及 UI 响应这些确定性条件。

本地 Release 编译及 Core / 协议检查、Windows 回归和发布附件数据待本轮验证后补充。现有旧渲染性能基准仍保留用于回归，其更早历史算法对比不算本轮新增提升。
