# 2.0.79 富文本语音输入兼容

## 问题与复现

用户在 Codex Windows 客户端先点击输入框，识别成功却只能手动复制。尚未收到该次诊断包，也未安装用户具体的 Codex 版本，因此不把测试样例当作该版本的实机验收。

Windows / Chrome 的失败回归 [41990401456](https://github.com/shouhuqingtian/snip/actions/runs/41990401456) 在提交 `6e9fff4` 复现：普通 textarea 和带 textbox 角色的 contenteditable 成功；带段落、没有 textbox 角色的富文本框失败，初次/最终 Editable 都为 false，原生焦点未变。

实际 Electron 38 默认启动并真实点击后，托管 UIA 可能只返回不可聚焦的 Document（类型 50030）；原生 MSAA 则返回真实文本/分组控件（role 42 / 20）。调查初期误将 50030 作为 Pane，导致兼容分支没有执行；通过阶段诊断确认后修正为匹配不可聚焦 Document。此前未执行分支不能据此认定原生接口不可用。修正后的 [41997082530](https://github.com/shouhuqingtian/snip/actions/runs/41997082530) 已实际完成 Electron 首次普通输入、语义富文本输入，以及同字段身份稳定/异字段身份不同；该轮仍因无角色分组编辑器缺少支持而失败，未放宽断言。

## 修改

- `VoiceWorkers.cs`：ValuePattern 不可用时读取 TextPattern 的明确只读属性，接受可编辑文档；未知或混合属性不视为可编辑。
- `BrowserHoverHitTest.cs`：对选定前台窗口的原生焦点查询，限定焦点链深度和原窗口归属；归一化 MSAA 的父对象/子编号，使用标准 IAccessibleEx.GetRuntimeId 获取字段身份，不使用 COM 代理指针或屏幕坐标代替身份。
- Electron 返回不可聚焦文档容器时，原生 MSAA 文本角色可通过明确的焦点/可聚焦/只读状态确认；非文本角色必须通过 IValueProvider / ITextProvider 返回明确只读属性，或由 IAccessible2 明确提供 EDITABLE 且不为 DEFUNCT，并与 MSAA 只读状态交叉检查。不接受不可用、隐藏、离屏或身份未知的控件。同一听写保持已选择的身份协议，之后每次重新查询状态，辅助进程结束即释放。
- `VoiceInputController.cs`：继续要求相同进程/RuntimeId、原生焦点未变化，保留键盘/鼠标操作保护、密码不上传、只读不输入、取消和迟到结果保护。日志只增加控件类型、只读/可聚焦、原生角色/状态、接口阶段/HResult和身份是否一致，不记录文字、名称、标题、网页地址或身份值。
- `VoiceInputStatusWindow.cs`：统一提示改为“未自动输入，结果已保留”，不把无法确认控件都称为输入位置变化。
- Windows 回归扩展普通/语义/无角色富文本/纯文本四类控件；新增真实 Electron 默认启动、真实点击后的第一次听写；随后检查重复身份、不同字段身份，以及只读、密码不上传和识别中换框。测试不强制开启渲染器无障碍开关，不用预先查询身份来掩盖首次使用问题。

原生接口依据 [Microsoft IAccessibleEx IDL](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/UIAutomationCore.idl) 和 [Chromium Windows accessibility 实现](https://github.com/chromium/chromium/blob/main/ui/accessibility/platform/ax_platform_node_win.cc)。试验中的 UIA 桥接与手工 IA2 uniqueID 调用已删除；IA2 get_states 使用官方固定 ABI（槽位 35），仅读取编辑/失效标记，身份仍使用 IAccessibleEx.GetRuntimeId。没有新增 UIA NuGet 包或用户侧原生 DLL。

`PrepareElectronFixture.ps1` 使用官方 Electron 38.0.0 Windows x64 测试运行时，SHA-256 固定为 `950591d9f3f97700973d5b594ae3833728192b9efd32b94be4d44ca0ef435e40`。仅用于验证，不随用户安装包分发；Windows 的 Desktop 验证会自动准备该依赖。测试使用合成音频和本地假 ASR，不调用付费平台。
