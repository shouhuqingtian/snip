# 2.0.54 桌面长截图冻结表头修复

用户反馈整个窗口和仅选正文都会频繁显示“对齐暂停”，稍快滚动也容易触发。检查复现三项缺陷：桌面复用了网页匹配的 20% 固定首尾区域限制；按整个选区高度的 1/4 累计滚动距离，大块工具栏/冻结表头会把正文挤得很小；仅等画面连续停稳才加入中间帧，连续滚动即使每对相邻画面可以可靠匹配，也会等到失去重叠才尝试拼接。

新增公开的 600 像素高画面回归：400 像素固定表头、40 像素固定底栏，正文只有 160 像素。每次滚动 32 像素，2.0.53 路径在测试中复现暂停；修复后要求逐像素匹配完整长图，固定区域只出现一次。用户截图和业务内容不进入代码或 CI。

另增加仅选正文的连续滚动回归：200 像素高选区以 32 像素连续移动，累计 192 像素，中间没有静止画面。停稳后才拼接的路径复现丢失内容；新路径必须完整生成 392 像素高长图，并拒绝混入无法匹配的动画噪声。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/Snip.Core/DesktopScrollMatching.cs` | 新增桌面专用运动匹配：同时排除源点与目标点上的静止区域，正反方向联合判断，固定首尾区域不受 20% 限制。最多 512 个分布式锚点限制计算量，支持取消；保持原有误差/唯一性门槛，重复内容不猜测。增加锚点数、候选数、误差、唯一性差距、首尾范围与拒绝原因等技术诊断。 |
| `src/Snip.Core/ManualScrollCaptureSession.cs` | 桌面按有效运动区域及时接收小步滚动，不再等待整个窗口的 1/4；采用联合方向判断。滚轮活跃时采样间隔从 80 ms 缩短至 40 ms；中间帧须通过更严格误差门槛（4）和唯一性检查，可靠时实时加入，不可匹配的动画帧忽略且不立即误报暂停；结束仍等尾帧稳定。原浏览器匹配路径不变。 |

| `tests/Snip.Core.Tests/ManualScrollCaptureTests.cs` | 加入连续运动原文像素的完整保留、不可匹配动画帧排除，保留过快跳过全部重叠时的拒绝/部分结果行为。 |
| `tests/Snip.Windows.Checks/DesktopScrollChecks.cs` | 在原表格/聊天真实外进程样例之外，增加半屏以上冻结表头、固定状态栏和原生单格滚轮样例，以及 180 像素正文选区每 90 ms 连续滚一格的场景；整张结果逐像素验证。 |
| `Directory.Build.props`、`docs/使用说明.md` | 版本与说明更新。 |

## 边界

本次修复针对固定区域占比较大的桌面选区，不能从完全相同的空白/重复内容中推断唯一滚动距离。一次滚动跨过全部重叠、动态重排或多个独立滚动区仍可能暂停；保留已采集部分而不强行拼接。具体 Excel、WPS、ChatGPT 桌面版本和用户的混合 DPI 屏幕仍需实机验证。
