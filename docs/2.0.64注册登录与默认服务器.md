# 2.0.64 注册、登录反馈与默认服务器

## 问题与修复

原先注册/登录和配置同步共用一行状态。认证成功后进入首次同步，状态会立即变为同步进度或错误，导致用户无法确认账号是否创建、是否登录成功。

现在顶部固定显示独立的账号结果：进行中、绿色“注册成功，已自动登录”或“登录成功”、红色注册/登录失败及具体原因。下方单独显示同步进度或红色“同步失败，可点击立即同步重试”。首次同步网络中断不会改写认证成功结果，之后自动轮询与手动同步也不覆盖。会话失效和退出会显示相应结果。注册提交后遇到网络超时或服务器错误、无法确定结果时，显示“注册结果未确认”并引导尝试登录，避免误报已失败。

注册与登录采用两个明确入口，移除邀请码输入。注册只需账号、密码、确认密码；失败时保留输入方便修改、切换登录或重试，成功与关闭窗口时清空密码。保留 12 位密码要求，因为该密码还用于客户端配置加密。

默认服务器 `https://bilibilil.online/selfsnip/`，仍可手动修改。复制 `https://bilibilil.online/selfsnip/health` 会自动归一为根地址，防止错误拼接登录接口；其他服务的路径前缀、端口及 HTTPS 校验保留。

## 服务端更新

本版服务默认允许无需邀请码注册。移除旧邀请码生成、部署必填环境变量和协议字段，继续保留注册限流、错误登录锁定、100 账号上限、客户端加密与会话撤销。管理员可设置 `SELF_SNIP_ALLOW_REGISTRATION=false` 暂停新注册，已有账号仍可登录。

需要同时更新服务器包至 2.0.64，只有更新客户端无法改变旧服务器的注册限制；旧服务器或关闭注册时会在客户端明确说明。原有账号、密码、会话和加密配置格式不变。systemd 环境文件、数据目录或 Docker 的 `.env`、`data/` 应保留。旧邀请码环境变量不再使用，不妨碍新版服务启动。见 [宝塔部署与更新步骤](宝塔部署账号同步.md)。本次没有服务器终端会话，未替用户执行线上更新。

## 修改文件

- `AccountSyncProtocol.cs`：默认地址、健康检查地址归一、移除邀请码字段。
- `AccountSyncApi.cs`：重复账号、密码错误及注册被服务器拒绝的明确说明。
- `AccountSyncService.cs`：认证与同步独立状态；区分已创建账号、本机登录、同步失败、取消与会话失效。
- `AccountSyncViewModel.cs`、`AccountSyncWindow.xaml/.cs`：顶部结果卡、独立同步卡、登录/注册入口、预填可编辑地址、失败保留输入、成功清空。
- `AccountStore.cs` 与 `packaging/account-sync/`：默认免邀请码注册和可选注册开关；安装时显式创建专用用户组。
- Core `AccountSyncTests`、HTTP `Snip.Sync.Checks`、Windows `AccountSyncChecks`：实际失败场景回归；检查公开样图的 workflow 增加新反馈截图选项。
