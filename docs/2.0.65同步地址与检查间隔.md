# 2.0.65 同步默认地址与自动检查间隔

## 修改

默认同步地址改为 `https://8.148.242.29/selfsnip/`，保留手动输入与 `/health` 地址归一。已保存的服务器/会话不自动迁移，避免向不同地址发送原会话。

自动检查从约每 30 秒改为约每 2 小时。空闲设备理论检查数由每天 2880 次降低为约 12 次（不含启动、登录和手动同步）；未变化时仍通过版本条件请求避免重复下载/上传。登录后、启动恢复会话后和“立即同步”仍立即执行。自动同步开关、冲突暂停和失败退避保留。配置检查只读取版本/按需同步，不运行翻译或 OCR 模型；降低频率主要减少网络请求。另一台持续运行的设备最多可能晚约两小时收到配置，需要时可手动立即同步。这个改动只涉及客户端，不要求更新已有 2.0.64 服务器。

## 本次连接问题的证据与边界

用户诊断包版本 2.0.64，2026-10-23 19:33（北京时间）记录 7 次账号请求失败；3 次注册、4 次读取登录账号参数。该版包装后的异常没有保留底层网络类型，不能仅据日志判断证书或代理原因。

用户补充浏览器健康检查返回正常 JSON；命令行默认路径连接本机代理失败。绕过代理后，在解析到原 ECS 地址后 TLS 握手被重置；IPv4/TLS 1.2 对照同样失败。它们表明两条路径均有连接问题，尚未确认是服务器 TLS、代理环境还是中间网络；不能声称更换 IP 已解决在线连接。

IP HTTPS 要求证书受信任并包含对应 IP 的 SAN，且 Nginx 将该 IP 请求匹配到同步服务站点。现有域名证书不自动覆盖 IP。没有关闭证书校验、降级 HTTP、自动绕过用户代理或自动改宝塔配置。

同时补全客户端连接错误：区分 HTTPS/TLS、代理隧道、域名解析及其他连接失败；保存底层异常供诊断日志提取类型/HResult/脱敏堆栈，并记录 HTTP 状态码与网络错误枚举。界面和日志均不输出底层异常消息、代理地址/密码、请求地址、账号或密钥。
