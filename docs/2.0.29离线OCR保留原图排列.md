# 2.0.29：离线 OCR 保留原图行列排列

用户反馈的核心问题是识别结果改变了原文编排。已确认两处原因：离线识别结果按文字框顶部精确 Y 坐标重排，同一行不同字体/字号的右侧值可能被排到左侧标签之前；显示端又把每个文字块强制换行，破坏表单、表格同行关系。

本次不替换模型、不新增下载，继续使用约 31 MiB 的 PP-OCRv6 small。

## 行为

- 先依据文字框高度和垂直重叠关系识别同一行，再按同一行从左到右排列，行按原图从上到下显示。
- 根据原图横向位置补空格，保留列间距和相对缩进；根据明显纵向空白补段落间隔，不改变识别出来的字词。
- 识别结果使用等宽排版，较宽内容横向滚动，不因结果框变窄而自动拆行。复制保留空格、换行。
- 文字区域的原始坐标、置信度、分块重叠去重保持，系统 OCR 和在线 OCR 原有文本输出继续沿用。

结果是可编辑纯文本，按坐标近似恢复行列与空白，不是还原字体、颜色、表格线的文档排版。保留原图预览供核对。当前针对中英横排截图；复杂杂志分栏、竖排、倾斜文字及合并单元格不承诺完整复刻。

## 验证

本地 Release 构建、119 项 Core 测试、39 项在线翻译和 17 项在线 OCR 协议检查通过。

独立 Linux/C# 真实引擎测试用公开生成的 3 行与 30 行中英表单：左右两侧字号、框顶部不同，旧精确 Y 排序均能复现错序，新行列输出正确。此项不冒充 Windows 桌面验收。

Windows 使用同类公开 WPF 表单，要求同时验证旧算法确实错序、新算法正确、跨分块不漏行，以及真实结果控件不折行、可横向查看、复制不丢空白。[Windows OCR 专项回归](https://github.com/shouhuqingtian/snip/actions/runs/38727686262)已通过：真实混合字号表单与 30 行分块样例验证旧算法错序、新排列正确；实际 WPF 采用等宽、不自动折行、可横向查看，复制保留空白。字符内容仍由既有识别测试单独核对。

首轮 Windows 样例未明确对齐不同字体的基线，行数检查未通过；调整为共享字体基线的同行样例并补上文字框坐标后复核，旧排序错误的断言和新结果完整性要求均保留。应用排版逻辑未为此放宽。

Windows 完整回归与最终 EXE 结果待本次发布验证后补充。
