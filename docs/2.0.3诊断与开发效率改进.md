## 验证方式

```powershell
./packaging/Validate.ps1 -Scope Core
# Windows 交互桌面，完成 Release 构建后
./packaging/Validate.ps1 -Scope Desktop -NoBuild
```

CI 会直接运行最终单文件 Snip.exe 导出诊断包，检查其退出码、显示器信息和完整源码提交版本。测试便携 ZIP 附 Windows 检查结果，Core 结果和所有失败输出在 Actions 附件中。具体通过/未执行结果以该提交的 Actions 和包内 JSON 为准。

## 后续修复流程

1. 用户提供操作现象和诊断 ZIP；先按 OperationId 看环境、最后阶段及异常。
2. 能复现时保存对应失败样例，修复后同一回归用例必须通过。
3. 编译/Core 快速检查先拦截错误，Windows 桌面检查再验证原生行为。
4. 检查通过自动发布测试便携版；反馈中带 build-info.json 版本，避免旧程序混淆。
5. 正式版本集中生成安装包。每项修改记录文件和实际验收范围。

## 边界

当前仍使用原生滚轮与画面匹配采集，浏览器扩展方案未在本轮实现。专用 Windows 开发机未配置，本轮使用已有原生 Windows CI。混合 DPI、多显示器、用户登录网页和微信发送仍需用户实机验收。自动样例不访问用户内网页面，也不证明所有网页均可采集。原生英语 OCR 缺少组件时明确写 Unrun；中文识别效果另行实测。

诊断默认不含截图/文字；如果算法问题仍需查看原始帧，应单独说明所需样例，由用户提供可分享的数据。本轮不自动上传诊断。
