# 自用截图 2.0.2：普通图文网页与窗口遮挡修复

用户反馈：整个网页截图在正常图文页面报告无法拼接，且软件的“正在自动滚动”窗口出现在截图中。

## 改动文件

| 问题 | 修改文件 | 处理方式 |
| --- | --- | --- |
| 软件进度窗/置顶贴图混入截图 | `src/Snip.App/Services/CaptureWindowScope.cs`、`FeatureHub.cs`、`src/Snip.Infrastructure/DesktopCaptureService.cs` | 不再显示浮动采集进度窗；采集期间隐藏软件自己的 WPF 窗口，结束或失败后恢复；抓取前等待桌面合成完成。 |
| 采集进度和取消 | `src/Snip.Infrastructure/TrayService.cs`、`src/Snip.App/App.xaml.cs`、`src/Snip.Core/Services.cs` | 托盘提示显示采集状态。Esc 取消；打开托盘菜单也先取消，避免菜单进入采集画面。忽略已结束任务的迟到进度回调。 |
| 白底文章/图片与固定工具条导致拼接失败 | `src/Snip.Core/ScrollMatching.cs` | 按移动的文字、图像边缘匹配，均匀分布采样点；过滤空白和保持原屏幕位置的工具条，避免白色背景稀释匹配信号。保留对真正歧义/不相关图像的拒绝。 |
| 空白区、页尾和悬浮栏重影 | `src/Snip.Core/ScrollCaptureSession.cs`、`src/Snip.Infrastructure/BrowserScrollCapture.cs` | 可用时使用浏览器的滚动百分比、可见比例和实际视口高度推导移动像素，与图像匹配交叉校验；无可靠移动位置时不猜测。拼接时更新重叠区域，用下一帧恢复先前被底部浮栏挡住的正文；短整页返回可见画面。 |
| 后台跨线程读图 | `src/Snip.Infrastructure/BrowserScrollCapture.cs` | 图像转换后立即冻结，并在等待滚动信息前读取尺寸，避免异步续读 WPF 图片引发跨线程访问异常；新增图文实机检查发现并验证了这条路径。 |
| 回归 | `tests/Snip.Core.Tests/SparseScrollTests.cs`、`tests/Snip.Windows.Checks/ChromeCaptureCheck.cs` | 白色边距、稀疏文字、固定底栏、空白页、短页面；Chrome 除彩色行页面外，新增白底文章 + 内嵌截图样式 SVG + 固定底栏，且在截图前放置真实置顶洋红色 WPF 窗口，验证隐藏、排除和恢复。 |
| 版本与交付 | `.csproj`、`MainWindow.xaml`、`packaging/Publish.ps1`、`packaging/Snip.nsi`、`.github/workflows/windows.yml` | 版本 2.0.2，自包含 EXE、安装包及完整源码。 |

## 使用

先从托盘退出旧版，再解压或安装 2.0.2。Ctrl+Alt+A 选取 Chrome/Edge 网页正文后，在 ↕ 菜单选择“捕捉整个网页”。采集时软件窗口隐藏，不再用浮动进度窗遮挡网页。Esc 取消；如需托盘菜单，打开菜单会先停止本次采集。

无限加载或动态改变布局的页面、没有移动特征且浏览器也未提供滚动位置的长空白段仍有原生屏幕采集的限制，遇到真实歧义时会停止，避免凭估计拼出错误长图。当前范围是普通网页的垂直整页截图，宽度为浏览器可见正文宽度。

发布脚本成功生成自包含 EXE 和 NSIS 安装包；ZIP 完整性、安装包内 EXE 与便携 EXE 一致，以及第三方归属说明已核对。下载目录使用同一份 2.0.2 源码在云环境发布的包，校验值见 downloads/SHA256SUMS.txt。
