# 2.0.50 网页弹层与粗粒度选区

修复网页弹层、弹层内 iframe 仍误选底层页面矩形的问题，并按用户反馈把自动选区改为较大区域：页面主体、弹窗、面板、列表和工具栏；不再逐个框选按钮、输入框、单元格、列表行。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/Snip.Infrastructure/BrowserHoverHitTest.cs` | 在指定 Chromium 窗口上调用辅助功能命中检测，沿实际命中的父链选容器，避免截图遮罩以及被网页弹层遮挡的兄弟节点；不读取文字、名称或网页地址。 |
| `src/Snip.Infrastructure/HoverRegionWorker.cs` | Chromium 优先使用命中路径，失败保留原生大区域；其他窗口保留 UI Automation，跳过原子控件，内部候选最小 160×96 DIP，随目标窗口 DPI 换算。 |
| `tests/Snip.Windows.Checks/SmartBrowserChecks.cs` | 实际 Chrome 公开页面复现底层行误选；检查 CSS 弹层、iframe 面板/空白处和多层弹窗，以及 Enter 冻结图像素；第 42 张预览。 |
| `tests/Snip.Windows.Checks/HoverRegionChecks.cs` | 普通 WPF 工具栏、输入面板、完整列表、面板的大区域选择；小按钮/字段/行不再独立框选；继续验证实际快捷键、Enter、超时、迟到保护、辅助进程回收与取消。 |
| `Directory.Build.props`、`docs/使用说明.md` | 版本与操作说明。 |

## 复现及验证

[未修复版本的真实 Windows 复现 39395940079](https://github.com/shouhuqingtian/snip/actions/runs/39395940079) 中，普通按钮/面板正常；弹窗覆盖底层列表行时，仍选出 650×28 的底层行而非 680×400 弹窗，用例按预期失败。该页和 iframe 都是测试生成的公开样例，无用户业务网页或账号。

修复后的专项、完整回归、安装包和附件验证结果在交付时补充。不保证未暴露辅助功能结构的自绘网页一定能自动框出弹层；无法可靠命中时退回较大区域，仍可手动拖选。
