# 2.0.16 通用 GPU 翻译加速

## 实现范围

同一个 Hy-MT2-1.8B Q3_K_M 模型支持 CPU 与 Vulkan GPU，无需为不同品牌重新下载模型。Windows x64 的 NVIDIA、AMD、Intel 设备只要符合官方 Vulkan 后端和驱动要求即可尝试；不承诺所有旧显卡或核显可用、一定比 CPU 快。

模式为自动、仅 CPU、优先 GPU。自动和优先 GPU 均在运行库已安装时检测兼容设备，优先可用内存最多的 Vulkan 设备（至少 1536 MiB 可用）；仅 CPU 不探测 GPU。GPU 运行库单独手动下载约 32.17 MB，解压约 80 MB，与 CPU 文件分目录，不重复安装 951 MB 权重，不自动更新显卡驱动、不要求 CUDA Toolkit。

只在离线翻译时探测/加载 GPU；在线模式不启用本机推理。GPU 使用指定设备、全部模型层、2048 上下文和 128 批大小以控制额外显存；确认官方推理器输出的数字化 GPU 层加载信号后才显示实际 GPU 后端。没有兼容设备、显存不足、驱动/启动/原生计算失败时先完整回收 GPU 工作进程，再最多尝试一次 CPU。用户取消不触发 CPU 重试，输入过长等非后端错误也不重试。

进程继续使用本机 127.0.0.1、随机临时鉴权、Windows Job Object 回收。设备探测不加载权重，8 秒截止，读取输出最多 64 KiB；原始驱动/模型输出不进入应用日志。GPU 工作进程只保留数字化加载层数，其他输出丢弃。取消、失败、完成关闭工作进程；闲置不保留模型或 GPU 进程。日志只记录计算模式、实际后端、层数、计数、耗时和工作集。

## 修改文件

- `src/Snip.Translation/translation-models.json`：官方 b11612 Windows Vulkan 压缩包及全部必需原生文件固定 SHA256/大小，保留原 CPU 文件摘要和模型。
- `src/Snip.Translation/ModelStore.cs`：CPU/GPU 独立运行库路径、校验与仅下载 GPU 运行库，共用安装锁和原权重。
- `src/Snip.Translation/TranslationComputeSettings.cs`：自动/CPU/GPU 偏好原子保存和无副作用读取。
- `src/Snip.Translation/GpuDeviceProbe.cs`：校验后使用原生 `--list-devices`，筛选兼容设备，限定输出、取消/超时及进程回收。
- `src/Snip.Translation/NativeTranslationHost.cs`：CPU 显式禁用 GPU；Vulkan 指定设备/层数，数字化层加载信号和实际后端，继续有界回收。
- `src/Snip.Translation/BackendExecution.cs`、`OfflineTranslator.cs`、`AssemblyInfo.cs`：GPU 后端错误一次 CPU 回退；先回收后重试，取消/输入错误不触发回退；给检查程序集开放内部流程测试。
- `src/Snip.App/ViewModels/TextResultViewModel.cs`、`Views/TextResultWindow.xaml`：计算方式选择和保存、GPU 下载进度及取消、实际计算方式；在线模式禁用本机 GPU 控件。
- `src/Snip.App/Services/FeatureHub.cs`：仅记录实际后端与加载层数等技术指标。
- `tests/Snip.Translation.Checks/ComputeBackendChecks.cs`、`Program.cs`：偏好持久化/损坏、跨品牌设备格式/显存选择、取消、单次回退/清理顺序、取消及输入错误不重试、固定文件清单。
- `tests/Snip.Translation.Checks/GpuRuntimeChecks.cs`：Windows 实际下载/校验 Vulkan 文件，不改原模型；隔离目录同大小 GPU 可执行文件篡改拒绝；无设备 CPU 回退、强制 CPU、进程回收。实体 GPU 推理与取消单列检查，没有设备标记 Unrun。
- `tests/Snip.Windows.Checks/TextWindowChecks.cs`、`NativeOcrCheck.cs`：真实 XAML 保存/重启与在线禁用、原生 OCR→翻译 UI 中显示的后端与实际指标一致。
- `packaging/Validate.ps1`：GPU 运行库回归与可选实体 GPU 回归分开记录，通过后打包。
- `Directory.Build.props`、`THIRD-PARTY-NOTICES.txt`、`docs/使用说明.md`：版本、官方运行库来源和使用边界。

## 当前验证

本地完整 Release 构建 0 警告、0 错误；75 项 Core、16 项计算设置/设备/回退检查、17 项在线协议及可用性检查通过。Linux 真实 CPU 双向问候、否定/数字/标识符、空行、同大小原生文件损坏、正在生成时取消与进程回收通过，合计工作集采样 1450.4～1476.2 MiB。Linux 结果不代替 Windows 桌面验证。

[Windows CI 38581694571](https://github.com/shouhuqingtian/snip/actions/runs/38581694571) 完成。16 组桌面检查中 15 组 Passed、0 Failed；仅 `gpu-inference` 因没有兼容实体 GPU 为 Unrun。GPU 运行库组真实下载官方压缩包、完整校验所有必需文件，不改原权重；隔离目录同大小 GPU 可执行文件损坏拒绝，无设备时优先 GPU 模式成功回退 CPU，安装 GPU 支持后强制 CPU 仍成功，工作进程均退出。真实 WPF 计算设置持久化、在线模式禁用、4K 原生 OCR→翻译界面实际后端显示、剪贴板、窗口位置及 Chrome 回归通过。4K CPU 结果窗口合计工作集峰值采样 1803.3 MiB，工作进程退出。

首次 Windows 界面检查发现新增设置挤压译文区至 64 DIP，已增大默认窗口及可滚动内容高度、明确文字框至少 70 DIP，保留原可读性断言；正常/紧凑窗口的真实渲染检查均通过。小屏仍可滚动，关闭/Esc 独立可用。

实体 GPU 推理、GPU 中途取消、实际显存和加速倍数尚未在兼容设备验证，不能把运行库校验、模拟错误回退或 CPU 推理当作实体 GPU 加速通过。可在有 Vulkan GPU 的 Windows 上运行 `dotnet run --project tests/Snip.Translation.Checks -c Release -- .model-cache/translation --gpu-runtime` 和 `--gpu-inference`，后者要求实际加载 GPU 层，否则 Failed；缺设备才 Unrun。界面本身显示实际使用的 CPU/GPU，以实机结果为准。
