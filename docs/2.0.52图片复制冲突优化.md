# 2.0.52 图片复制冲突优化

诊断记录确认：2.0.51 在 2026-10-21 14:29:41（北京时间）复制 747×588 截图时，`Clipboard.Flush` 抛出 `0x800401D0`，总计等待 5876 毫秒；14:29:56 再次复制在 39 毫秒内成功，14:30:12 后续复制在 35 毫秒内成功。日志未丢弃、写入失败为 0。旧图片复制每次重试都会再次执行 WPF/OLE 的设置与持久化刷新，临时占用会叠加框架内部等待。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/Snip.Infrastructure/NativeImageClipboard.cs` | 冻结原图后后台准备一份原生 CF_DIBV5 数据；保留像素、方向、颜色及透明通道，Windows 提供标准 Bitmap/DIB 转换。直接写入立即可用的数据，不依赖 OLE 延迟渲染或 Flush。仅占用时进行 7 次异步间隔、共 8 次尝试，等待间隔合计 1280 毫秒；同进程复制串行化，排队最多 1600 毫秒。 |
| `src/Snip.Infrastructure/ImageExportService.cs` | 图片复制统一使用原生实现；增加取消与阶段进度重载，保留原接口的调用兼容性；PNG 保存不变。 |
| `src/Snip.App/Services/DiagnosticImageExport.cs` | 增加准备、数据就绪、占用次数、可获取的占用进程 ID、发布和取消阶段；不记录截图、剪贴板内容、窗口标题或进程名。 |
| `src/Snip.App/Services/CopyFeedbackExport.cs` | 传递取消与阶段进度；成功后才显示提示，取消不产生迟到提示。 |
| `src/Snip.App/ViewModels/EditorViewModel.cs` | 导出接受取消令牌；失败保留截图/标注与未导出状态，恢复复制入口；显示正在复制/失败保留状态。 |
| `src/Snip.App/Services/SelectionSession.cs` | 截图取消/布局变化/退出时取消待执行的图片写入，不再在关闭截图后发布旧图或显示失败弹窗。 |
| `tests/Snip.Windows.Checks/ImageClipboardChecks.cs`、`Program.cs` | 新增原生专项：真实外进程占用下复现旧 Flush 异常；连续第二张图片、短占用自动恢复、界面心跳、持续占用保留编辑与剪贴板、释放后重试、Esc 取消无迟到、生产进程退出后图片仍可读、标准格式兼容、16 次连续复制、透明度及 3072×1920 图片；并加入基础 Windows 套件。 |
| `tests/Snip.Windows.Checks/ClipboardWindowChecks.cs` | 复用实际外进程占用器，提供消息窗口以便核对占用 PID；文字复制原有检查保留。 |
| `.github/workflows/windows-targeted.yml`、`Directory.Build.props`、`docs/使用说明.md` | 新专项入口、版本及说明。 |
