# 2.0.73 语音设置快捷键与识别配置修复

## 已确认的问题与修改

2.0.72 的 App 在语音设置窗口前台时，会把截图、贴图和已注册的语音快捷键直接转交给快捷键草稿，不检查是否正在编辑。用户没有点击快捷键栏，也可能改变草稿并无法使用截图快捷键。修复为：

- 明确点击“修改快捷键”或快捷键框才进入录入状态；窗口打开、Tab 获得焦点不进入录入。
- 一个有效组合只录入一次，然后退出；Esc、焦点移到其他控件或切换窗口取消录入。
- 只有录入期间才接管已经注册的截图/贴图/语音组合；其他时候正常截图与贴图。语音设置窗口前台仍不启动录音。
- 草稿必须保存才改变工作中的语音快捷键，已有冲突保留逻辑继续使用。

用户截图中的 MiniMax `speech_to_text` 地址与 `asr-1.0` 模型为自行填写；未提供官方识别文档。本程序的自定义识别使用 OpenAI 兼容的 multipart 上传与 JSON `text` 返回，不能把发音服务的地址/模型直接当成识别接口。设置页增加协议与同平台密钥说明，MiniMax 地址显示尚未适配专用识别协议的提示；不自动更换平台、密钥或发送付费请求。

HTTP 失败现在显示状态码，区分 400/422 参数或协议、401/403 密钥权限、404 接口模型、405/415 上传方式、429 限流额度、5xx 服务异常。响应正文不进入错误提示或诊断。最近一次安全失败说明保留在本次运行中，重新打开设置可查看；下次录音或成功保存后清除。

## 服务和模型示例的来源

保留硅基流动 SenseVoiceSmall、OpenAI `gpt-4o-mini-transcribe` / `gpt-4o-transcribe` / `whisper-1`。新增：

- Groq：`https://api.groq.com/openai/v1/audio/transcriptions`，`whisper-large-v3-turbo`、`whisper-large-v3`。依据 [官方 Python SDK](https://github.com/groq/groq-python/blob/main/src/groq/resources/audio/transcriptions.py)、[参数定义](https://github.com/groq/groq-python/blob/main/src/groq/types/audio/transcription_create_params.py) 与 [客户端默认域名](https://github.com/groq/groq-python/blob/main/src/groq/_client.py)。
- Fireworks：`https://audio-prod.us-virginia-1.direct.fireworks.ai/v1/audio/transcriptions`，`whisper-v3`。依据 [官方示例的归档版本](https://github.com/fw-ai/cookbook/blob/57968a2237b663be33078d2747a28463983ae134/archived/learn/audio/audio_prerecorded_speech_to_text/audio_prerecorded_speech_to_text.ipynb)。该示例为官方归档内容，线上服务的开放范围、权限和有效期需以平台为准。

开发环境访问 MiniMax、硅基流动、Groq、Fireworks 的官方文档站均遇到网络网关 403。可访问的 MiniMax 官方 MCP 仓库 [0856b9a](https://github.com/MiniMax-AI/MiniMax-MCP/tree/0856b9aef8a9d676bb63bdd6b6426d7b640a3b7a) 列有语音合成等工具，但不足以确认上述自行填写的识别接口。未据此推断 MiniMax 不提供任何识别服务，也未添加未经核实的 MiniMax 识别预设。

所有预设仍可编辑。各平台需要自己的账号权限、密钥、网络条件和额度；预设来源核对不代表使用真实密钥完成线上识别验收。实际麦克风和付费平台效果需在用户设备试用。
