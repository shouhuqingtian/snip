# 离线翻译单模型选型：Hy-MT2-1.8B Q3_K_M

**接入进展：用户确认后已在 2.0.14 替换为唯一离线模型，并完成 Windows 真实推理与 4K 结果窗口验证。** 下载方式、修改文件和实际内存见[接入记录](2.0.14单模型离线翻译接入.md)。以下为选择模型时的调研记录。

2026-10-14 第二轮调研。用户要求只保留一个离线翻译模型，不做模型选择或旧模型回退；预算仍为下载约 1 GB、运行内存约 2 GB，中英双向翻译。本轮只做调研、下载校验和候选实际推理，应用当前模型尚未替换。

## 唯一推荐

**Hy-MT2-1.8B Q3_K_M**，使用 Unsloth 提供的常规 GGUF 量化版本。它是翻译专项模型，支持中英双向、术语、上下文及格式要求，基础模型采用 Apache-2.0。Q3 量化文件实际下载并校验为 **951,022,560 字节，即 951 MB / 907 MiB**。

此前仅核对了 Hy-MT2 官方 Q4 与极低位版本。扩大检索后找到常规 Q3 版本并实际执行，文件大小已落入预算，因此本轮推荐从第一轮 HY-MT1.5 更新为 Hy-MT2。第一轮的数据保留作历史记录，不再作为另一个待接入模型。

采用常规 Q3_K_M，不使用需要特定 ARM/STQ 内核的 2bit/1.25bit 版本。使用官方 llama.cpp b11612 常规 Linux x86_64 CPU 推理成功；该发行也提供约 19.6 MB 的 Windows x64 CPU 包，说明有可用的 Windows 分发形态，但本轮未在 Windows 执行模型，也没有测量 Windows 整应用峰值。

## 跨来源筛选

读取了 Hugging Face 的官方/量化模型卡、文件大小和固定版本元数据；GitHub 上腾讯、Google Research、SMALL-100、OpenNMT 和 llama.cpp 的官方资料；腾讯 HY-MT1.5 的 GitHub 技术报告 PDF；并实际运行 Hy-MT2 候选。

| 专用翻译模型 | 已核对大小 | 筛选结果 |
| --- | --- | --- |
| **Hy-MT2-1.8B Q3_K_M** | 单文件 951 MB | 预算内，公开原模型评测、术语/格式能力明确，8 句 CPU 推理成功；唯一推荐 |
| HY-MT1.5-1.8B Q3_K_M | 单文件 951 MB | 第一轮已测试；同等体积下本轮优先评估新一代模型，保持单模型方案 |
| SMALL-100 INT8 | 权重 339 MB；所查仓库总文件约 342 MB | 更省空间，论文侧重低资源多语；没有相同条件中英结果证明其适合替代本轮候选，不因体积最小就选它 |
| NLLB-200 distilled 600M INT8 | 权重 623 MB；所查仓库总文件约 647 MB | 专门的多语翻译；原模型定位研究、CC-BY-NC-4.0，官方还说明句长/领域限制；本轮未实测质量和峰值 |
| M2M100 418M | 原始权重约 1,936 MB | 支持中英，CTranslate2 支持转换；原始文件超预算，不能将参数量直接当成量化体积或质量依据 |

INT8 大小引用对应社区转换仓库的元数据，不是将 FP32 大小简单除以 4。仓库总文件大小也不等于最终安装包所需文件，尤其 SMALL-100 的 tokenizer 需另外核对。没有对未执行的候选编造内存或质量实测。

## 公开评测怎样理解

腾讯官方 Hy-MT2 图表中，原始 **1.8B** 模型的 WildMTBench 为 **86.74**、WMT25 为 **60.33**、FLORES-200 为 **79.20**。这些是作者公布的评测指标分数，不是准确率，不是独立机构的最终排名，也不是本次 Q3 量化文件的评分。不同模型报告的测试口径不能直接混比。

[官方模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B) · [官方仓库与评测图](https://github.com/Tencent-Hunyuan/Hy-MT2) · [图表文件](https://raw.githubusercontent.com/Tencent-Hunyuan/Hy-MT2/main/imgs/main_result.png) · [论文链接](https://arxiv.org/abs/2605.22064)

本轮读到了官方模型卡和评测图；论文站受网络代理限制，未读取 Hy-MT2 全文。HY-MT1.5 的技术报告通过官方 GitHub PDF 实际读取了 13 页。这里不宣称已经在统一测试集复现官方评分，也不保证超过在线 DeepSeek/通义千问。

## 候选实际推理

Linux x86_64，llama.cpp b11612，纯 CPU 2 线程，上下文 1024，最大输出 192 token，贪心采样。按官方翻译提示格式执行；每句新进程，文件系统缓存已热。八次退出码均为 0。
