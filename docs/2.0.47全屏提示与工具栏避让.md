# 2.0.47 全屏选区提示与工具栏避让

## 修复

全屏或贴近屏幕上边缘的选区，工具栏可能回退到左上角，与原来固定在 `(16,16)` 的尺寸/操作提示重叠。现在按工具栏和提示的实际测量尺寸，在同一窗口 DIP 坐标内安排位置：发生冲突时，提示优先放在工具栏下方；下方没有空间时改放上方，必要时预留顶部提示行。

提示保持可见且不拦截鼠标，小屏或高缩放下按可用宽度换行。工具栏换行、窗口尺寸变化、重新选择区域后重新安排。修改只影响截图辅助界面，不更改选区、原图像素、标注或导出尺寸。

[Windows 布局专项 39367333001](https://github.com/shouhuqingtian/snip/actions/runs/39367333001) 通过，[保存日志复核 39367484700](https://github.com/shouhuqingtian/snip/actions/runs/39367484700) 确认全部 38 张主题窗口预览成功。新增 12 个布局场景同时检查立即布局和稳定布局，覆盖全屏、上下边缘、普通选区，另检查重新选区复位与原图像素一致。

缩放场景使用真实窗口的不同 DIP 大小覆盖布局；不能替代用户两块物理显示器的实机验证。测试使用公开的 1280×800 像素底图；正式运行中，最大窗口受 CI 桌面限制，实际为 **1044×788 DIP**，另两档实际为 **960×600**、**640×500 DIP**。以 `selection-layout.json` 的实际尺寸为准，日志中的 1280×800 为请求的最大窗口尺寸，不是实测窗口尺寸。

首轮 Windows 专项检查捕获到 640×500 DIP 下的第二个问题：工具栏绑定/模板完成后实际高于首次测量值，提示仍可能覆盖换行后的工具栏。保留原断言，布局改为同时使用测量高度和实际渲染高度，并在 `SizeChanged` 时修正；用例同时检查立即布局和消息循环处理后的稳定布局，不添加持续逐帧布局监听。
