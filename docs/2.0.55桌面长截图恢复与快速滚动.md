# 2.0.55 桌面长截图恢复与快速滚动

用户反馈向上回到采集末尾后仍暂停，连续滚动仍慢。先补公开回归复现三项问题：返回略早于末尾的位置仍持续显示暂停；正文回到原位置但冻结工具栏颜色变化时无法解除暂停；大量重复网格和空白列让真实文字的滚动匹配被拒绝。旧代码在三项测试中失败，修复后须验证完整输出像素和恢复状态，不能只核对高度。

## 验证

本地 Release 构建 0 警告、0 错误；177 项 Core、47 项在线翻译协议、17 项在线 OCR、21 项 AI 语音协议/生命周期检查通过。真实 Windows 专项、完整回归及安装交付完成后补充证据。

在同一 Linux 进程对 1600×600 的公开合成画面分别预热 30 次、记录 10 次：高纹理样例中旧匹配中位 37.256 ms，新匹配 6.634 ms，偏移均为 120；稀疏表格旧匹配 2.849 ms 但拒绝，新匹配 4.958 ms 且正确得到 120。该微基准不是抓帧、应用滚动或用户设备的整体速度保证；索引也不会让所有输入都更快。Windows 原生输入和结果像素仍需单独验证。

## 边界

软件观察手动滚轮，不修改目标应用的滚轮速度。加速的是采集和匹配，以跟上更快的操作。完全跳过重叠、只有重复网格/空白、内容动态重排或多块区域同时独立滚动时，仍无法可靠推断唯一偏移，不能强行拼接。恢复要求画面与采集末尾有可识别的重叠；不是任意回到已采集的很远位置就能立即续接。具体 Excel、WPS、ChatGPT 版本和混合 DPI 仍需实机验证。

最初 Windows 专项在未发布提交 `331a546` 中拦住两项缺陷：仅保留已命中指纹的点使相似行被误接；从文字锚点位置推断固定首尾会把普通网页留白误当固定区域，快滚时导致边界不一致。已修复验证点选择与首尾判断，再进行原生回归；失败构建未发布。
