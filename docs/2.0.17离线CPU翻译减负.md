# 2.0.17 离线 CPU 翻译减负

## 问题与证据

用户反馈离线翻译速度慢、占用高，已确认实际显示 CPU。比较同一个已校验 Hy-MT2 模型的公开英文问候和付款条款，发现只减小计算批次不能明显降低峰值；CPU 默认权重重排产生额外内存布局及加载开销。关闭重排后模型内容、精度、提示词及上下文保持原配置，没有换模型或降低输出长度。

正式同轮比较交替启动 3 次旧配置、3 次新配置，使用相同公开付款条款、新工作进程和相同结束条件。本地 Linux 中位原生峰值 1391.2 → 1099.9 MiB（约降低 21%），加载加翻译 2.48 → 1.89 秒（约缩短 24%）。每个进程均退出。此比较排除模型 SHA256 校验及 UI/OCR时间，不能当作用户点击到结果的统一承诺。

## 改动

- 关闭 CPU 权重重排（`--no-repack`），不创建额外重排权重副本。
- 计算批次 512、物理批次 128，保留 2048 上下文、原输出上限及同一模型。
- CPU 生成线程为逻辑处理器数约一半、最多 4；输入处理保留一个逻辑处理器、最多 4；单核至少 1。不是无限增加线程。
- Windows CPU 工作进程尝试 BelowNormal 优先级，减轻对桌面交互的调度影响。
- 完成/取消/失败仍释放工作进程。保留完整模型/运行库校验，不通过跳过校验或驻留模型制造速度提升。
- GPU 和在线模式保留原参数；仅本地 CPU 路径采用新配置。

## 修改文件

- `src/Snip.Translation/CpuInferenceProfile.cs`：有界 CPU 线程和内存参数，内部保留旧参数供同轮对比。
- `src/Snip.Translation/NativeTranslationHost.cs`：CPU 参数、低优先级尝试、CPU 计算时间采样。
- `src/Snip.Translation/OfflineTranslator.cs`、`src/Snip.App/Services/FeatureHub.cs`：记录参数和累计 CPU 秒数等技术信息，继续保护原文/译文。
- `tests/Snip.Translation.Checks/TranslationPerformanceChecks.cs`、`Program.cs`：交替 3 轮旧/新真实后端比较，检查模型意义、非截断输出、峰值至少减少 10%、无重大速度退步及进程回收。
- `tests/Snip.Translation.Checks/ComputeBackendChecks.cs`：单核/双核/4/8/16/64 逻辑处理器均有线程上限及较小批次，不保留重排副本。
- `tests/Snip.Windows.Checks/NativeOcrCheck.cs`：实际 4K OCR→翻译 UI 校验使用 CPU 有界参数且关闭额外重排。
- `packaging/Validate.ps1`：Windows 新增同轮性能对比检查，失败不发布。
- `Directory.Build.props`、`docs/使用说明.md`：版本及使用边界。

## 验证

本地完整 Release 构建无警告/错误，75 项 Core、22 项计算配置/回退检查、17 项在线协议/可用性检查通过。Linux 新参数真实中英问候、否定/金额/代码标识符、空行、文件损坏拒绝、生成中取消和进程回收整组通过，父子进程合计工作集采样 1158.5～1187.6 MiB。[Windows CI 38590499697](https://github.com/shouhuqingtian/snip/actions/runs/38590499697) 通过。17 组桌面检查中 16 Passed、0 Failed，实体 GPU 推理因无兼容硬件仍 Unrun，本次只处理已确认的 CPU 情况。真实双向翻译、原生 OCR、生成中取消、文件损坏拒绝、窗口/剪贴板、Chrome、GPU 运行库/CPU 回退均通过。

Windows 同轮 3 次旧/3 次新配置的中位数：

| 指标 | 旧 CPU 参数 | 新 CPU 参数 |
| --- | ---: | ---: |
| 原生峰值工作集 | 1390.6 MiB | 1099.4 MiB |
| 模型加载 | 1.38 秒 | 1.06 秒 |
| 加载 + 翻译样例 | 3.45 秒 | 3.07 秒 |
| 累计 CPU 计算时间 | 5.81 秒 | 6.89 秒 |

原生峰值约减少 20.9%，样例总耗时约缩短 11.2%。**CPU 累计计算时间约增加 18.5%**，因此本次不能宣称降低了 CPU 总计算量或瞬时占用。较低内存布局和适度并行在该 Windows 后端上有这个取舍；较低进程优先级有助让出桌面调度，不保证所有机器 CPU 图表更低。用户的速度、耗电和输入规模仍需实机验证。

实际 4K 截图 OCR→新 CPU 模型→可见结果流程峰值父子合计 **1516.1 MiB（约 1.48 GiB）**，原生 1098.0 MiB，进程释放。2.0.16 相同 4K 样例的历史记录是 1803.3 MiB；它是跨次 CI 对照，不能当作同轮严格百分比测试。模型本身约 951 MB，不能把整句离线翻译的整体内存保证成几十 MB。
