# 2.0.44 软件自身窗口截图

## 原因与行为

旧版开始截图时先隐藏本进程所有可见 WPF 窗口，窗口预选又过滤当前进程，所以文字工作台、编辑器、贴图和主窗口都会从截图中消失。这是应用逻辑的限制，不是 Windows 禁止程序截取自己。

现在按 Ctrl+Alt+A、自定义截图快捷键、托盘截图或点击主窗口“开始截图”，都会保留当前可见的软件窗口，包括发起截图的主窗口。先冻结桌面，再显示覆盖层；默认高亮也支持自身窗口，直接 Enter 复制，或拖动重选、标注、保存。不新增开关，不改变已有快捷键。

正在进行的一次选区仍不能重复唤起第二次截图；保留单会话保护，截图覆盖层在冻结桌面之后才创建，不会截入自身。网页长截图继续使用其专有的窗口隐藏/恢复范围，避免控制窗口挡住浏览器采集；本轮不改变浏览器目标枚举的默认行为。

## 修改文件

| 文件 | 修改 |
| --- | --- |
| `src/Snip.App/Services/CaptureCoordinator.cs` | 取消普通截图前隐藏所有应用窗口及结束后重新显示的流程；截图入口统一保留自身窗口；预选枚举显式允许本进程。 |
| `src/Snip.Infrastructure/WindowCaptureInfo.cs` | 为 Snapshot 增加可选 includeCurrentProcess 参数，默认仍排除本进程，截图工作流按需启用。 |
| `tests/Snip.Windows.Checks/SelfCaptureChecks.cs`、`HotkeyChecks.cs` | 通过真实 CaptureCoordinator、RegisterHotKey、WPF 主窗口按钮和原生 Enter 验证自身窗口截图、实际置顶贴图、逐像素剪贴板比对、取消和采屏失败；加入既有 hotkey 桌面组。 |
| `Directory.Build.props`、`docs/使用说明.md` | 2.0.44 版本与最新截图行为说明。 |
