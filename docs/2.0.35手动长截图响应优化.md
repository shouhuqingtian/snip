# 2.0.35 手动长截图响应优化

## 定位与修改

手动拖选路径中，原先每个鼠标移动都同步改变 WPF 选框，并唤醒采集循环、回送进度；选框由覆盖整个网页的透明 WPF 窗口承载。高频鼠标事件与高分辨率下，这些操作会增加输入线程和透明表面的绘制负担。入口还会尝试可选的 UIA 滚动接口；原生查询超时后后台查询可能仍在执行。

| 改动 | 文件 | 结果 |
| --- | --- | --- |
| 轻量边框 | `src/Snip.Infrastructure/CaptureOutline.cs`、`src/Snip.App/Services/ManualScrollCaptureController.cs` | 用四条窄的非激活合成表面替代整块透明网页窗口；直接使用物理像素，不在每次移动中重新查询 DPI。取图时明确隐藏，关闭时销毁。 |
| 合并刷新 | 同上、`src/Snip.App/ViewModels/ManualScrollCaptureViewModel.cs` | 鼠标回调只更新最新坐标和一次待刷新标记，选框及尺寸提示约每 33 ms 合并更新；空闲时刷新定时器停止。隐藏取图期间，队列中的刷新不能重新显示边框。 |
| 减少唤醒 | `src/Snip.Core/DragScrollCaptureSession.cs` | 普通移动仍更新最终坐标，但仅开始、进入/离开滚动边缘、松开、完成等状态变化唤醒采集，不再每个鼠标事件都发送进度。 |
| 入口准备 | `src/Snip.Infrastructure/BrowserScrollCapture.cs` | 手动模式跳过可选的 UIA 滚动接口探测与每帧位置查询，使用实际图像拼接位移；整页/从当前位置向下的行为保留。仍严格判断图像匹配，未降低阈值。 |
| 导出内存 | `src/Snip.Core/ScrollFrameAccumulator.cs`、`DragScrollCaptureSession.cs` | 直接按选区从已保存的正文和最后一帧固定页脚导出，不先分配另一张全宽长图再裁剪。 |
| 回归与测量 | `tests/Snip.Core.Tests/DragCapturePerformanceTests.cs`、`tests/Snip.Windows.Checks/ManualPreviewChecks.cs`、`ChromeCaptureCheck.cs`、`Program.cs`、`RenderPerformanceCheck.cs`、`.github/workflows/windows-targeted.yml` | 核对 1000 次移动合并、边缘/松开信号、固定页脚裁剪、4K 窄选区分配量；真实窗口边框颜色、隐藏后像素干净、焦点/关闭，以及真实 Chrome 进入时间、连续 80 次原生移动时 UI 调度与最终截图像素。 |
| 交付 | `Directory.Build.props`、`packaging/Publish.ps1`、`.github/workflows/windows.yml` | 版本 2.0.35。正式 ZIP 采用 ASCII 文件名，SHA256 清单对应用户实际下载文件名，继续使用同提交已验证 EXE 构建安装包。 |

## 验证与边界

本地 Release 编译 0 警告、0 错误；131 项 Core、47 项在线翻译协议、17 项在线 OCR 协议检查通过。新增 Core 检查验证正文修复/固定页脚交界的裁剪像素与原先完整导出一致；3840×2160 底图导出 320×1700 选区时，新增分配仅为选区像素及少量对象开销。

4K、2 像素边框的表面面积从整块窗口的 8,294,400 像素变为四条边合计 23,984 像素。这是绘制面积对比，不是整个软件内存或速度的百分比。实际准备时间与输入响应以 Windows 测量结果为准，完成后补充。

操作仍是按住左键拖选，到网页下沿自动滚动，松开完成；Esc 取消。等待拖选时不持续截屏。动态网页、无法可靠对齐的内容仍会提示停止；用户双屏混合 DPI 的实际手感需实机确认。
