# 自用截图：Ubuntu 私有账号同步服务

这是自建账号服务，不是登录阿里云账号。部署后，在两台电脑的“账号与同步”中填写同一个 HTTPS 服务地址和自用截图账号。

## 部署

1. 在 Ubuntu 安装 Docker Engine 和 Compose 插件：https://docs.docker.com/engine/install/ubuntu/ 。
2. 下载并解压同版本 `self-snip-sync-server-<版本>.zip` 到固定目录；目录内应包含 `app/`、`compose.yaml`、`Dockerfile` 和本说明。
3. 在这个目录执行 `sudo bash setup.sh`。脚本生成私有 `.env` 和邀请码，仅修改当前目录内的 `data/` 属主，容器服务只监听 `127.0.0.1:5080`。
4. 将 `nginx-location.conf` 的 location 段加入现有域名的 HTTPS `server { ... }` 块。保留现有证书和其他网站配置；先备份站点配置，执行 `sudo nginx -t` 成功后再 `sudo systemctl reload nginx`。本脚本不会自动修改或重启现有网站。
5. 浏览器打开 `https://你的域名/selfsnip/health`，应得到 `{"status":"ok","version":1}`。只有 HTTP、证书错误或重定向到其他地址时，先修好 HTTPS 反代。无需开放公网 5080 端口。

若已有别的进程占用 5080，可在 `.env` 修改 `SELF_SNIP_PORT`，并同步修改 Nginx 的 proxy_pass 端口，再重新执行 setup.sh。

Docker 官方镜像下载是否顺利取决于服务器网络；脚本不自动添加第三方镜像源。如果拉取失败，请使用你信任的镜像加速配置后重试。

## 两台电脑如何使用

1. 工作电脑升级对应版本，主窗口打开“账号与同步”，服务地址填写 `https://你的域名/selfsnip/`。
2. 勾选“首次使用：注册新账号”，输入 3–64 位英文/数字账号、至少 12 位密码，再确认密码。邀请码从服务器部署目录 `.env` 的 `SELF_SNIP_REGISTER_INVITE` 读取，填到客户端的“注册邀请码”。它不是模型密钥。
3. 点击“注册并登录”。云端为空时，会将本机服务配置加密上传。
4. 家里电脑输入同一个服务地址、账号和密码，直接点击“登录并同步”，无需再次注册。
5. 默认约每 30 秒检查变化，也可“立即同步”。本机和云端同时有修改时自动暂停，选择“使用云端配置”或“上传本机配置”。已有本机配置的设备首次登录也会提示选择方向。
6. 导入云端配置前，请关闭在线设置、AI 语音设置、通用设置窗口，以免覆盖未保存的编辑。退出同步账号只退出此设备，不删除本机模型密钥。

## 范围与数据保护

同步仅包含翻译/在线 OCR/AI 语音的服务地址、模型、音色、密钥及默认方式。截图、识别文字、翻译历史、诊断包、快捷键和模型文件不参与同步。

原始账号密码仅在客户端派生密钥，不会发送或保存。PBKDF2-SHA256（600,000 次）与 HMAC 的不同用途标签分别派生账号认证凭据、配置加密凭据；服务器保存认证凭据的 ASP.NET Identity 哈希。配置包采用独立随机盐/nonce 的 AES-256-GCM 认证加密。客户端会话与配置解密凭据由当前 Windows 用户的 DPAPI 保护；模型密钥导入后同样按本机用户重新加密。

密码忘记后，服务端无法直接恢复云端配置。仍保留本机配置的电脑可注册一个新账号并重新上传。第一版不提供忘记密码找回或密码修改接口，请妥善保存密码。共享邀请码只用于受邀注册，部署后可更换它，既有账号不受影响。

会话有效期 30 天，每账号最多 8 个设备会话；登录失败 5 次暂停该账号登录 15 分钟，并有请求限流。配置上传采用版本比较，拒绝过期版本。服务不记录请求体、认证头、模型密钥或原始密码；请保持 Nginx 使用常规日志格式，不额外记录请求体或 Authorization。

服务设计为单实例、私有小规模部署，最多 100 个受邀账号。数据使用原子文件替换与进程独占锁，不支持多个副本共享目录。`data/` 同时保存账号哈希和加密配置包，请定期备份；备份并不替代客户端密码。

## 更新和回退

先备份 `.env` 和 `data/`。停止服务：`docker compose down`；更新部署包的 `app/` 和部署文件，保留 `.env`、`data/`，再执行 `sudo bash setup.sh`。卸载时只有明确不再需要账号及云端配置，才手动删除数据目录。

构建版本与提交见 `server-build-info.json`。发布验证使用本地真实 HTTP 服务与公开合成密钥，没有连接或验证用户的实际阿里云实例、域名证书或 Nginx 站点。
